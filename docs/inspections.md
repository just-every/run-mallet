# Reusable digital inspections

Open a repair's **Digital inspections**. Owners and service advisors define reusable service recipes (real part/labor lines and current USD prices), then create a vehicle/service template. Points may map to an exact recipe revision. Assign a template to the repair's current technician. The assigned checklist keeps that exact revision even after the reusable template changes.

A measurement names what was observed and its explicit unit. For qualitative checks, define the name/unit (for example Condition / grade) and one grade label per line (for example Good, Worn, Replace). The technician selects a label; no numeric measurement is invented. Physical values keep their entered units without conversion.

The current technician records green, yellow, red or not inspected, always with a reason. Yellow/red additionally requires the configured measurement/grade and a completed photo belonging to the same repair. Capture/upload it in **Inspection photos & video**, return and choose it by finding and filename. Photo originals and prepared variants remain private under DVI-002; a prepared variant does not mean sent. A skipped point stays incomplete with its reason. Recording again appends evidence and keeps all earlier observations.

An owner or service advisor can prepare a mapped recipe from a current yellow/red finding. The action shows the current recipe revision and prices; the resulting estimate freezes both the original mapping and the priced recipe revision alongside the original observation and checklist. It does not approve, send or authorize work. A repair with an existing customer decision gets a separate EST-004 supplement; an undecided existing draft must be handled explicitly before another estimate can be prepared.

The public command door supports `inspectionJob.save`, `inspectionTemplate.save`, `inspection.assign`, `inspection.record` and `inspection.estimate`. Reusable records use exact record versions (zero for new records). Assignments name an exact template revision, current template version and current job version. Observations use the current job and inspection versions, point ID, outcome, reason, exact measurement value/unit and, for yellow/red, a completed `photoUploadId`. Numeric `measurementValue` is a number; a configured grade is its exact label string. Template measurements can include `grades: ["Good", "Worn", "Replace"]`. Each template/recipe accepts up to 100 points/lines; native editors grow with each saved revision.

Only the currently assigned technician records observations. Owners/service advisors manage templates, recipes, assignments and mapped estimates; technicians see only their assigned checklist snapshots. Agents receive no inspection records, events or raw inspection provenance. Native session/origin checks and the write transaction recheck authority. Full native archives retain template and recipe versions, assignments, results, grade labels, original photo custody and bytes, and estimate source snapshots; restored historical attribution grants no old identity access.
